# v2.0 実装・検証メモ

## 検証結果（2026-11-16、Playwright 1.63 + ヘッドレスChromium）

| 対象 | 結果 |
| --- | --- |
| 既存テスト16本（辞典・命名・科学医学・漢字神話・拡張・ブラウザ4本ほか） | すべて成功 |
| 旧版（v1.6基準）との固定乱数比較 `verify-dictionary-gacha.cjs` | 2592件の生成結果が一致 |
| `verify-studio-core.cjs`（共通データ構造） | 10グループ成功 |
| `verify-browser-studio.cjs`（新機能の実ブラウザ検証） | 10グループ成功、コンソールエラー0 |

既存テストの変更は、タイトルとフッターの版数表記（v1.7→v2.0）を確認している2行のみです。

`verify-browser-studio.cjs` が確認している主な点：

- 既存の保存リスト `ocMakerSavedV1` が、登録・取り込み・作品操作の後もバイト単位で同一であること
- 立ち絵の縮尺：形の違う2枚の画像（200×400と300×300）が、頭頂・足元の指定によって同じ身長の高さに描かれること（計算値と実際の画素の両方）
- 同じ二人の間の3本の関係線が、ラベルが重ならずに描かれること
- 改名・身長変更・所属の変更が他のタブに反映されること、キャラ削除時に影響が表示され関連データが掃除されること
- 画像つきバックアップの書き出しと復元（新しい作品として取り込み、既存は不変）、壊れたファイルの拒否
- 390pxと320pxで全タブに横はみ出しがないこと、タッチでの線引き・人物のドラッグ・頭頂線のドラッグ
- IndexedDBが使えない環境でも生成と図鑑（メモリ保存）が動くこと

画面とPNG出力の見本は `studio-browser/` にあります。

## 未確認・既知の制約

- **実機のiPhone Safariでは未確認です。** 検証はヘッドレスChromiumのスマホ相当設定（タッチ有効）で行いました。特に、2本指の拡大縮小、画像選択（写真ライブラリ）、PNGの長押し保存、ダウンロード時の日本語ファイル名は実機での確認が必要です。
- テキスト欄の自動伸長（CSS `field-sizing`）は対応ブラウザのみ。未対応のブラウザでは手動で広げられます。
- 画像は長辺1600pxに縮小して保存します。原寸は保持しません。
- バックアップは画像をBase64でJSONに含めるため、画像が多い作品ではファイルが大きくなります。
- 相関図の線は人物の中心同士を結ぶ曲線で、線の経路を手で曲げる機能はありません。
- 世界観の歴史は手動の並べ替え（↑↓）です。年代による自動整列はありません。
- 生成結果には身長が含まれないため、身長は図鑑または身長比較で入力します。
